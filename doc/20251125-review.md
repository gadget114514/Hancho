## 1. 全体評価・良かった点

前回のレビュー（`doc/20261125-argon-review.md`）で残課題として挙げられていた未完了カード（**102-1, 102-5, 102-6, 102-7, 102-8, 102-9, 102-10**）およびテスト・ドキュメントの指摘事項がすべて網羅的に実装されており、0.10.0 の設計思想（`task` → `direction` → `job` → `attempt`）がコードベース全体で一貫して完成しています。

### 1.1 102-x シリーズの完全実装とパフォーマンス改善
- **Overlapped Pipe I/O (`102-1`)**:
  - `src/ipc_client.cpp` で `Sleep(10)` ポーリングが廃止され、`FILE_FLAG_OVERLAPPED` + イベント待機に移行。タイムアウト時は `CancelIoEx` 後に `GetOverlappedResult(..., TRUE)` で確実に完了待ちしてからスタック上の `OVERLAPPED` を破棄する安全な実装になっている。
- **仮想リスト化 (`102-5`)**:
  - `src/gui_dashboard.cpp` のタスク一覧 ListView が `LVS_OWNERDATA` / `LVN_GETDISPINFOW` / `ListView_SetItemCountEx` に移行。
  - フラット表示での列ソート時にも、`SortTaskRows` で `rows` と `taskDisplayRows` を同じインデックス順で同時に並べ替えることで、クリック操作やインデント参照のインデックスずれを防いでいる。
- **トリアージの差分更新 (`102-8`) と Direction 単位化 (`102-10`, `102-7`)**:
  - `src/triage_manager.cpp` の `Refresh()` が `TaskQueueChanges(lastTaskRev_)` による差分同期になり、`List()` も `storeRev_|mode_|llmMode_|state` キーでキャッシュ化されている。
  - `BuildDirectionFailureCard` により 1 direction につき最大 1 枚の `direction_failure` カードに集約され、BT 実行途中の fix ループ内失敗ではカードを作らない仕様がクリーンに実装されている。
  - 100-8 の繰り返し失敗（`lineage_repeated_failure`）も、別カードを増やさず direction カード上の `repeatedFailure` バッジに統合されている。
  - 0.10 以前の `job:<id>` 暗黙 direction について、`src/direction_store.cpp` でファイル名上の `:` を `_` にサニタイズしつつ JSON 内の `id` フィールドをキーにロードすることで、Windows のファイル名制約を綺麗に回避して永続化・一括クローズ（`direction close --state failed --before ...`）に対応している。
- **負荷試験ハーネス (`102-9`)**:
  - `tools/loadtest/run-loadtest.ps1` と `HANCHO_PERF_OUT` 環境変数による計測スコープ（`PerfOutScope`、未設定時はオーバーヘッドゼロ）が整備されている。

### 1.2 `card` コマンドの `direction` への統合と用語統一
- CLI / MCP / WebUI の表層インターフェースが `direction <add|list|show|edit|remove|run|redo|import|export|translate|close|reopen|purge>`（日本語 UI 表記: `指示`）に統一された。
- 一方で `src/ipc_server.cpp` では `card_*` アクションも内部互換として同じハンドラにマッピングしており、既存の内部処理やスクリプトを壊さない安全な移行になっている。

### 1.3 3行 KPI カード・ルーチン管理ダイアログ・展開状態保持
- プロセス / タスク / ジョブの 3 行 KPI を設定ダイアログの「KPI」タブから動的に表示切り替えでき、非表示の行を詰めてツールバー位置を自動調整する設計（`ActiveKpiRowCount`）が導入された。
- ツールバーの「ルーチン」ボタンから開くルーチン管理ダイアログ（定義プレビュー・入力差分チェック・実行・承認／却下）、および「全部閉じる」ボタンと `InitializeTaskExpandedOverrides` による展開状態の安定保持が丁寧に実装されている。

## 2. 指摘事項（バグ・改善提案）

### 【中】2.1 3行 KPI 化に伴う「ジョブ行（3行目）」のクリック判定・アニメーション漏れ

KPI カードが 16 枚（2行）から 24 枚（3行: `0..7` プロセス、`8..15` タスク、`16..23` ジョブ）に拡張されましたが、`src/gui_dashboard.cpp` の以下の箇所が旧2行（`0..15`）のインデックスのままになっています。

1. **トリアージカードのクリック判定 (`src/gui_dashboard.cpp:23622-23637`)**:
   - 設定の KPI タブで「タスク KPI 行（`8..15`）」を非表示にして「ジョブ KPI 行（`16..23`）」を表示している場合、第3行右端の「ジョブ判断待ち」カードはインデックス **`23`** に描画されます。
   - しかし `WM_LBUTTONDOWN` では `st->kpiCardRects[15]` と `for (int i : {7, 15})` しか判定していないため、**カード `23`（「ジョブ判断待ち」およびその下部の「自動 未確認 / 要フォロー」）をクリックしてもトリアージ画面が開きません**。
   - **修正案**: サブ領域判定を `{15, 23}` の両方で行い、カード本体のクリック判定も `for (int i : {7, 15, 23})` に広げる。
2. **稼働中バーのアニメーション再描画 (`src/gui_dashboard.cpp:23513-23518`)**:
   - `TIMER_KPI_ANIM_ID` で `InvalidateRect` しているのが `kpiCardRects[1]`（稼働中プロセス）と `kpiCardRects[9]`（稼働中タスク）のみで、**`kpiCardRects[17]`（稼働中ジョブ）と `kpiCardRects[21]`（保留/ブロック中ジョブ）が含まれていません**（描画側の `src/gui_dashboard.cpp:3278, 3299` では `g_kpiBarPhase` を渡しているため、60ms タイマーで再描画されずバーが止まって見えます）。
   - **修正案**: `InvalidateRect(hwnd, &st->kpiCardRects[17], FALSE);`（および必要に応じて `[21]`）を追加する。
3. **KPI 表示行数が変わった際のツールバー再配置条件 (`src/gui_dashboard.cpp:9327`)**:
   - `toolbarMoved` が `(width != st->lastToolbarWidth || usageOffset != st->lastToolbarUsageOffset)` のみを見ています。設定画面のチェックボックス変更時は `st->lastToolbarWidth = -1` で強制再配置していますが、`LoadShellConfig` 等で `activeKpiRows` が変わった場合にも追従できるよう、`yBar`（または `activeKpiRows`）の変化も条件に含めるとより堅牢です。

### 【中】2.2 タスクカード（`card` テンプレートの BT direction）に対するトリアージ `redo`（救済）の挙動

`src/triage_manager.cpp:1033-1086` の `candidateId == "redo" && !directionId.empty()` の処理について：
- 現在の実装は、`failedJobIds` の各ジョブを `TaskQueueGet` で取得し、`jobId + "-r" + (hops + 1)` として `TaskQueueAdd` で単発ジョブ群の新しい `jobs` direction を作成しています。
- これは `taskqueue add` 由来の `jobs` direction に対しては適切ですが、**タスクカード（`direction add` / `direction run` で `card` テンプレートの BT として走った direction）が失敗した場合**、`TaskQueueAdd` で失敗リーフジョブ（たとえば `test` ジョブだけ）を単発キューに入れると、BT 構造（`impl` → `build` → `test` の fix ループ）やカード番号（`<number>-r1`）を持たない `jobs` direction になってしまいます。
- **対応完了（2026-11-25）**: `directionStore_` 上のレコードに `card` オブジェクト（`card.number`）が存在する場合は、`tqm_.CardRedo` + `btm_->CardRun` に委譲し、救済 direction（`<number>-r1`）を生成・実行するよう修正。返却メッセージも direction 用語（`"Created rescue direction " + rescueDirId + " (" + newNumber + ")."`）に統一した。

### 【低】2.3 `bt_start` での `triage: false` 設定タイミングの微小な競合窓

`src/ipc_server.cpp:3177-3189` で、`btm_->Start(...)` の呼び出し直後に `tqm_.SetDirectionTriage(dirId, false, triageErr)` を呼んでいます。
- `btm_->Start` の内部で `EnsureBtDirection` が呼ばれてツリーが別スレッドで即座に動き始めるため、ツリーが極端に早く失敗し、かつその瞬間に 1 秒周期の `TriageManager::Refresh()` が走ると、`SetDirectionTriage(dirId, false)` が反映される前に 1 回だけ `triage: true`（既定値）として見られる微小な競合窓があります。
- **対応完了（2026-11-25）**: `BtManager::Start` および `TaskQueueManager::EnsureBtDirection` に `bool triage = true` 引数を追加し、direction レコード作成時に直接 `"triage": false` を書き込むよう修正。`src/ipc_server.cpp` の `bt_start` からも直接 `btm_->Start(..., triage)` へ渡すことで競合窓を完全に解消した。
