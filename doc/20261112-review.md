- **レビュー対象**: コミット `5cda68b` ("Release v0.9.5: browser UI, TUI, remote streaming, and usage rollups") および関連する直近のコミット群

### ② `tests/bt_ipc_smoke.cpp`: Test 16（ストリーミング反映テスト）の配信未実装
- **ファイル**: [tests/bt_ipc_smoke.cpp#L972-L1045](file:///D:/wsgit/Hancho/tests/bt_ipc_smoke.cpp#L972-L1045)
- **現象**: 以下の4件のアサーションが失敗する。
  ```text
  FAIL: Streamed event 1 kind is plan
  FAIL: Event 2 is thought
  FAIL: Event 3 is tool.call
  FAIL: Event 4 is run.ended
  ```
- **原因**: Test 16 において `listener.SetHandler` がダミー JSON レスポンス（`{"ok":true, ...}`）を同期的に返すだけで、Test 15 のように IPC サーバーを経由させたり、ファイル監視を行って WebSocket クライアントへイベントを push する処理が存在しない。
- **対処案**: Test 15 同様に IPC サーバーハンドラを経由させるか、`listener.BroadcastStream` を用いてイベントを明示的に配信する構成に修正する。

---

### ③ `tests/bt_ipc_smoke.cpp`: Test 17（`taskqueue_counts`）のデータディレクトリ未分離
- **ファイル**: [tests/bt_ipc_smoke.cpp#L1073](file:///D:/wsgit/Hancho/tests/bt_ipc_smoke.cpp#L1073)
- **現象**: `FAIL: taskqueue_counts total is 0 initially`
- **原因**: `IpcTestHarness` が `SetDataDirectoryOverride` を設定していないため、実行マシンの既定ログフォルダ（`logs/taskqueues/`）に残存する過去のタスクキュー・ジョブファイルを読み込んでしまい、`total == 0` の前提が崩れている。
- **対処案**: `IpcTestHarness` のコンストラクタでユニークな一時ディレクトリを作成して `SetDataDirectoryOverride` を設定し、デストラクタでクリーンアップを行う。

---

### ④ `tests/headless_smoke.cpp`: IPC パラメータ不整合 & タイミング問題
- **ファイル**: [tests/headless_smoke.cpp](file:///D:/wsgit/Hancho/tests/headless_smoke.cpp)
- **現象**:
  1. `DEBUG: tqAddResp={"error":"job 'headless_smoke_job_1': timeout_sec is required and must be greater than 0","ok":false}`
     - 266行目の `tqJob` 定義で必須フィールド `timeout_sec` が欠落している。
  2. `FAIL: headless core lists task queues via IPC`
     - 281行目で `tqListResp["queues"].is_array()` を検証しているが、現在の `taskqueue_list` IPC レスポンスは `"jobs"` を配列として返却する設計となっているためキー不一致。
  3. `FAIL: job continues and finishes after client reconnects`
     - Step 2b で追加されたスタンドアロン GUI の起動・待機・終了処理に約3秒以上を要するため、テストジョブ（`ping -n 4`）が Step 3 の `wait` 呼び出し前にすでに完了してしまい、`wait` 判定が空振り（`waited=0`）する。
- **対処案**:
  - `tqJob` に `{"timeout_sec", 30}` を追加。
  - レスポンス検証を `tqListResp.contains("jobs")` または `taskqueue_counts` の検証に変更。
  - テストジョブの実行時間を延長するか、Step 3 の判定で完了済み（`snap.state == ProcState::Completed`）も正常完了として扱う。

### ⑤ `tests/behavior_tree_smoke_part2.cpp`: NTFS タイムスタンプ精度競合
- **ファイル**: [tests/behavior_tree_smoke_part2.cpp#L48-L51](file:///D:/wsgit/Hancho/tests/behavior_tree_smoke_part2.cpp#L48-L51)
- **現象**: `FAIL: all 7 condition types succeeded`
- **原因**: 48行目で `after_j1.txt` を書き出す際、ジョブ開始時刻（`j1.start`）と同一ミリ秒内に書き込みが行われると、NTFS のタイムスタンプ判定で `fileNewer` 条件が成立しない場合がある。
- **対処案**: ファイル作成前後にミリ秒単位のスリープを挟むか、明示的に未来のファイル時刻を設定する。

## 4. アーキテクチャ & 実装品質レビュー (Architecture & Quality)

### A. Browser UI (`src/webui_server.cpp`, `webui_assets.cpp`, `src/webui/app.js`)
- **長所**:
  - **インラインコンパイル & 開発用フォールバック**: 全 Web アセットが `src/webui_assets.cpp` にコンパイル時に組み込まれており、外部アセットなしで単一バイナリ配布が可能。かつ `HANCHO_WEBUI_DIR` 環境変数によるホットリロードにも対応。
  - **セキュリティ**: ローカルホスト (`127.0.0.1`) へのバインドを徹底。URL パスの `..` によるパストラバーサル検証、トークン認証を考慮した設計。
- **改善点**:
  - `src/webui/app.js`（約1,400行）が単一ファイルで肥大化傾向。将来的な拡張（コンポーネント分割・ES Modules化）が推奨される。

### B. TUI Dashboard Top (`src/cli_top.h`)
- **長所**:
  - ヘッダオンリーで POSIX（termios / ioctl）と Windows（conio / Console API）を両対応。
  - VT100 エスケープシーケンスを用いたダブルバッファリング的描画により、高速かつちらつきの少ない更新を実現。
  - 1〜5キーによる画面タブ切り替え（Overview / Tasks / Processes / Resource Locks / Usage）が GUI 版の機能セットと完全に一致している。
- **改善点**:
  - 1,700行規模の単一ヘッダとなっているため、入力処理 (`top_input.h`)、レンダリング (`top_view.h`)、状態管理 (`top_state.h`) への分割が望ましい。

### C. リモートストリーミング & 多重化 (`src/remote_client.cpp`, `src/ipc_server_remote.cpp`)
- **長所**:
  - 単一の WebSocket 接続で複数ジョブのログ tail とイベントストリームを多重化（Multiplexing）する設計。
  - `seq` 番号を用いた購読・再送プロトコルにより、ネットワーク一時切断後の再接続時にもイベントの取りこぼしや重複が発生しない。

### D. タスクキュー & リソースロック (`src/taskqueue.cpp`)
- **長所**:
  - 各ジョブが宣言する `resources.read` / `resources.write` に基づく競合検出 (`FindRunningResourceConflictLocked`) が的確に動作。
  - 共有ロック（複数同時 Read）と排他ロック（Write 排他）が並行タスクスケジューラ内で破綻なく統合されている。
