## 2. 新規追加機能のレビュー（Task / Direction 見出し行の情報拡充 & UI 表記整理）

今回のコミット `d8e67bc` および未コミット差分で追加された機能についての評価です。

1. **TaskHeading / DirectionHeading の開始・終了時刻、実行中詳細、Origin 表示 ([task_lineage_view.h:489-765](file:///D:/wsgit/hancho/src/task_lineage_view.h#L489-L765), [gui_dashboard.cpp:7980-8110](file:///D:/wsgit/hancho/src/gui_dashboard.cpp#L7980-L8110))**:
   - **開始時刻 (`startTime`)**: 配下のジョブの最初の `attempt.start` から算出し、未実行（`planned`）のカードでは空（`-`）にする配慮が入っており直感的です。
   - **終了時刻 (`endTime`) と所要時間**: 終端状態（`succeeded` / `failed` / `cancelled` / `closed`）のときのみ `closed.at` または最新 `attempt.end` / `updated_at` を表示し、ダッシュボード側で `(XmYs)` の所要時間も併記されるようになりました。
   - **実行中詳細 (`runningDetail`)**: Task 見出し行には現在動いている Direction（`110-2: Second Card` など）、Direction 見出し行には現在動いている Job（`j_110_2: Running job` など）が列7（実行中内容）に表示されるようになり、折りたたんだ状態でも進行箇所が一目で分かります。
   - **Origin 継承**: Task / Direction レコード自身に `origin` がない場合でも配下の最初のジョブから `origin` を補完して表示・ホバーツールチップに出すようになっており、実用性が高いです（[taskqueue_smoke.cpp:5049-5140](file:///D:/wsgit/hancho/tests/taskqueue_smoke.cpp#L5049-L5140) で単体テスト済み）。
2. **未コミット差分（`src/gui_dashboard.cpp` の KPI 表記微調整）**:
   - タスク KPI 行の「タスク総数」から冗長なサブ表記（`ジョブ N`）を外してすっきりさせ（3行目のジョブ総数カードと役割分担）、カード 14 のラベルを `指示 / カード` (`DIRECTIONS / CARDS`) から `指示` (`DIRECTIONS`) に統一した変更です。用語統一（`direction` = `指示`）に沿った良い変更です。

## 3. 軽微な改善提案（重箱の隅レベル）

機能上の不具合は残っていませんが、細部で2点だけ共有します。

### 【低】3.1 Origin コンボボックスの件数集計に見出し行（TaskHeading / DirectionHeading）も加算される点
[gui_dashboard.cpp:7966-8123](file:///D:/wsgit/hancho/src/gui_dashboard.cpp#L7966-L8123) において、今回 `TaskHeading` と `DirectionHeading` にも `row.cells[10]`（Origin 列）が入り、`++originCounts[row.cells[10]]` で Origin コンボボックスの件数にカウントされるようになりましたが、`st->taskOriginFilter` による絞り込み判定は依然としてジョブ行（8482行目: `if (!st->taskOriginFilter.empty() && TaskRowIsRealJob(jobId) && row.cells[10] != st->taskOriginFilter) continue;`）にのみ存在します。
- 実際は TaskHeading / DirectionHeading は `st->taskOriginFilter` が設定されていてもフィルタで弾かれずそのまま表示されるため**親見出しが消えてしまう問題は起きません**が、`++originCounts[row.cells[10]]` を TaskHeading / DirectionHeading / Job の3階層すべてで加算しているため、**Origin コンボボックスに表示される件数 `(N)` が「実ジョブ数＋タスク見出し数＋Direction見出し数」の合計値**になります。
- **提案**: Origin コンボボックスのカウント（`++originCounts[row.cells[10]]`）は従来どおり実ジョブ行（8479行目）だけで数えるか、あるいは見出し行は Origin 表示だけにとどめて `originCounts` には加算しないようにすると、コンボボックス上の件数表示が実ジョブ数と一致してより正確になります。
