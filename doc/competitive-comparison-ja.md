# Hancho: 競合比較

**[English](competitive-comparison.md) | [日本語 (Japanese)](competitive-comparison-ja.md)**

Hancho はエージェントフレームワークではありません。既存の CLI エージェントを OS プロセスとして動かし、その作業状態を耐久的に保持する**プロセス外の制御プレーン**です。以下のツールの多くは別の層を解くものなので、優劣ではなく向き不向きの比較です。

[README](../README-ja.md) に戻る。[Pros/Cons](pros-cons-comparison-ja.md) と [批判的比較](critical-comparison-ja.md) も参照してください。

---

## 1. 各ツールの位置づけ

| | 分類 | 実行モデル | 強み | 弱み | Hancho との関係 |
|---|---|---|---|---|---|
| **Hancho**（本プロジェクト） | CLI プロセスの制御プレーン | OS プロセス（pipe / ConPTY）、タスクキュー、ビヘイビアツリー | 耐久ジョブ、タイムアウト、再試行、リソースロック、ログ、`.done`、GUI、異種 CLI の混在、失敗分析、セッションをまたぐメモリ | Windows 中心（POSIX / リモートは初期段階）、LLM のコンテキスト管理はしない、RAG / ベクトル DB は非同梱、エコシステムが小さい | — |
| **LangChain / LangGraph** | エージェント / オーケストレーション | アプリ内のコード、グラフ / チェーン | 豊富な統合、RAG、メモリ抽象化、グラフのチェックポイント、トレース（LangSmith） | プロセス監督と任意 CLI の制御は自前、アプリ内実行、SDK / ベンダー依存 | 補完。LangGraph の処理を Hancho のジョブとして走らせ、耐久性・再試行・一覧性を得る |
| **AutoGen** | マルチエージェント | アプリ内の会話型エージェント、イベント駆動 | マルチエージェント会話、ツール利用、柔軟な役割 | 任意 CLI の OS プロセス監督、耐久キュー、GUI はなし | 補完。AutoGen の runner を Hancho のジョブにする |
| **CrewAI** | マルチエージェント | アプリ内のクルー / フロー | 役割・タスク・フローを素早く表現できる | 任意 CLI の監督、再起動耐性、運用の可観測性は弱い | 補完。クルーの実行を Hancho で監督する |
| **Claude Agent SDK / OpenAI Agents SDK** | ベンダー製エージェント SDK | アプリ内 / ヘッドレス | ツール、ハンドオフ、ガードレール、トレース、型付き制御 | ベンダー依存、プロセス管理・ログ・再試行は自前 | 補完。SDK のスクリプトを監督下のジョブとして実行する |
| **Mem0 / Letta / Zep** | メモリサービス / ライブラリ | エージェントの隣のサービス / ライブラリ | 抽出、要約、ベクトル / グラフ検索、ユーザー / セッション記憶 | 作業のオーケストレーションはしない、抽出は LLM 依存で非決定的、OS の実行状態は持たない | 補完。リッチな意味検索に使い、Hancho は決定的な実行記録と人の承認済み知識を持つ |

## 2. メモリ機能の比較

| | Hancho | LangChain 風の階層型メモリ | Mem0 / Letta / Zep |
|---|---|---|---|
| 単位 | **試行（L1）/ 事実（L2, L3）** | 会話、メッセージ、要約 | ユーザー、セッション、事実 |
| 持続性 | プロセス・セッション・再起動・エンジンをまたぐ | 1 つのアプリ内。永続化は自前 | サービス側で永続 |
| 決定性 | L1 はイベントから決定的。L2/L3 は明示的で監査できる | 要約と検索が損失的で非決定的 | 抽出が LLM 依存で非決定的 |
| 人の承認 | **L3 への昇格は人だけ** | なし | なし / 限定的 |
| 検索 | BM25 相当のキーワード検索。埋め込みは任意の `IMemoryRanker` 境界 | ループ内のベクトル / 要約検索 | ベクトル / グラフ検索 |
| 強み | 実際に走った事実に紐づき、監査できる | 長い会話をコンテキスト窓に収める | 強力な意味検索と抽出 |
| 弱み | RAG / 埋め込みは非同梱 | 他のプロセスやセッションを見られない | 実行制御とは無関係 |

Hancho のメモリは**作業のメモリ**であり、会話メモリや文書 RAG の置き換えではありません。文書検索が目的なら、LangChain、LlamaIndex、Mem0 などを Hancho のジョブとして動かして併用します。

## 3. どれを使うか

- **Hancho**: 複数の CLI エージェントや普通のコマンド、再起動をまたぐ長時間作業、OS レベルのタイムアウトとプロセスツリー制御、ダッシュボード、失敗分類、セッションをまたぐ事実と人の承認済み知識。
- **LangChain / LangGraph**: アプリ内にエージェントや RAG パイプラインを構築し、グラフ制御・統合・トレースを使う。
- **AutoGen / CrewAI**: 1 つのアプリ内で役割ベースのマルチエージェント会話やフローを回す。
- **Claude / OpenAI Agent SDK**: ベンダー統合のエージェントをツール・ハンドオフ・ガードレール付きで作る。
- **Mem0 / Letta / Zep**: エージェントの隣に高品質な抽出・意味メモリを置く。

Hancho に最も合う組み合わせは、**Hancho が実行を監督し、フレームワークがエージェントを作り、メモリサービスがリッチな検索を担う**形です。Hancho は「1 つのプロセスや 1 つの会話を超えて残る、検査可能な作業」が必要な限り有用です。
