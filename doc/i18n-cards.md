# データは英語で持ち、表示するときに訳す — タスクカード 106-1〜106-6

状態: タスクカードまで書いた（2026-11-24）。未着手。0.10 系（`main`）。106-3 のカードの表示と 106-5 の取り込みは、タスクカードの保存（104-x、`doc/task-card-store-cards.md`）を前提にする。

用語は `doc/terminology.md` に合わせる（task / direction / job / タスクカード）。

## なぜやるか

- Hancho は、メニューや見出しのような固定の文言だけを `Tr(L"日本語", L"English", L"Español")` で表示言語に合わせている。ジョブの `summary`、BT の名前とノードの `summary`、direction・task の `title`、カードの本文、トリアージの理由（LLM の助言）、メモリのノートは、書かれた文字列をそのまま保存して、そのまま表示している。
- そのため、日本語で指示された supervisor が日本語で書くと、英語やスペイン語の UI にも日本語が出る。`doc/` のタスクカードも日本語なので、104-4 の取り込みが入ると、カードの一覧が日本語で並ぶ。
- Hancho 自身も日本語を保存している所がある。`src/taskqueue.cpp` が書くメモリのノート（「<job> は直近 3 回 … で失敗」「… は所要時間がタイムアウトに近い」）は日本語の固定文で、どの言語の UI でも日本語で出る。
- skill（`skills/hancho/SKILL.md`）が日本語なので、それを読んだ supervisor は日本語で書きがちになる。
- このままでは GitHub で公開しても、日本語の読めない人には使えない画面になる（2026-11-24、ユーザー）。

## 方針

**保存するデータの言語は英語。表示するときに、表示言語に合わせて訳す（2026-11-24、ユーザー）。**

- 自由文の項目（下の「対象の項目」）は英語で保存する。supervisor には英語で書くよう skill とツールの説明で求める。英語以外で来たら、原文を残したうえで英語に訳して保存する（106-5）。
- Hancho が自分で作る文（メモリのノートなど）は英語で保存する。言語ごとに変えたい文は、保存時に文にせず、種類と値（`failure_streak`、`failureClass` など）で持ち、表示時に `Tr()` で組み立てる（トリアージの `triage_text.cpp` の `Pick(lang, ...)` と同じ作り）。
- 表示言語が英語以外のとき、ダッシュボードは訳文のキャッシュがあればそれを出す。なければ英語の原文を出し、裏で訳を作り、できたら差し替える。表示が訳を待って止まることはない。
- 訳は LLM で作る。登録済みのエンジンを使い、オフにもできる。オフや失敗のときは英語のまま出る（今と同じ見え方）。

## 仮の決定

| 項目 | 仮の答え |
|---|---|
| 表示言語 | 今の `UiLanguage`（ja / en / es）。訳すのは ja と es だけ |
| キャッシュ | データディレクトリの `translations/<lang>.json`。キーは原文の UTF-8 のハッシュ。値に原文・訳文・エンジン・モデル・作成時刻・最後に使った時刻を持ち、引くときに原文が一致するか確かめる（ハッシュの衝突と原文の変更に備える）。上限 20,000 件、最後に使ったのが古いものから捨てる（使っている訳は捨てない） |
| 訳し直さない | **同じ原文・同じ言語は 1 度だけ訳す（2026-11-24、ユーザー）。** 表示のたび、描き直しのたび、言語の切り替えのたび、再起動のたびに訳し直さない。訳し直すのは、原文が変わったとき（キーが変わる）と、ユーザーが明示したとき（`translate_clear`）だけ。エンジンやモデルを変えても、既存の訳は捨てない |
| 訳すエンジン | `config.json` の `translate_engine` / `translate_model`。省いたら `triage_llm_engine` / `triage_llm_model`、それもなければ訳さない |
| 有効・無効 | `translate_mode`: `auto`（既定。表示言語が英語以外で、エンジンが決まっているときだけ動く）/ `off` |
| 呼び出し方 | トリアージの LLM と同じく、プロセスとして起動する（`req.name = "translate-llm"`）。並列は 1。足りない文をまとめて 1 回で頼む（最大 50 件・合計 8,000 文字）。返事は JSON の配列（入力と同じ順） |
| 使用量 | 使用量の集計に `kind: "translate"` で載せる。トリアージの LLM と区別できるようにする |
| 英語以外の判定 | ひらがな・カタカナ・漢字・ハングルが入っていれば英語以外とみなす。スペイン語などラテン文字の言語は自動では判定しない（呼び出し側が `sourceLang` を付けたときだけ扱う） |
| 原文の保持 | 英語以外で来た項目は、本体を英語に置き換え、原文を `<項目>Source: {lang, text}` に残す。訳ができるまでは本体に原文を入れ、`<項目>Lang` に言語を入れておく |

## 106-1: Hancho が保存する文を英語にする・英語で書くよう求める

ファイル: `src/taskqueue.cpp`、`src/gui_dashboard.cpp`（メモリのノートの表示）、`src/mcp_server.cpp`、`src/cli.cpp`、`skills/hancho/SKILL.md`、`tests/taskqueue_smoke.cpp`。

- `src/` で、保存するデータ（ジョブ、BT、direction、メモリ、トリアージのカード、ログの JSON）に入る文字列リテラルから、日本語のものを探して全部直す。今わかっているのは `taskqueue.cpp` の自動ノート 2 種（失敗の連続、タイムアウトに近い）。UI に出すだけの `Tr()` / `Pick()` は対象外。
- 自動ノートは英語の文で保存する（例: `build failed 3 times in a row: success_check_failed (filesNewer)`）。種類と値は今の `tags` に加えて、ノートに `data: {kind, job, failureClass, condition, p90, timeoutSec}` として持つ。ダッシュボードは `data` があれば `Tr()` で表示言語の文を組み立て、なければ `text` をそのまま出す（106-3 の訳とは別。これは訳さずに済む）。
- `taskqueue_add`、`bt_start`、`taskqueue_update` などの MCP ツールの説明と、CLI のヘルプの `summary` / `title` の説明に「英語で書く（表示は Hancho が訳す）」を足す。
- `skills/hancho/SKILL.md` に「summary・title・カード・理由は英語で書く。ユーザーとの会話の言語に合わせない」を足す（skill 全体の英語化は 106-6）。
- `taskqueue_add` / `bt_start` で、`summary` / `title` に英語以外（上の判定）が入っていたら、結果に警告（`warnings: ["summary is not English: ..."]`）を付ける。拒否はしない（106-5 が入れば英語に直して保存する）。
- テスト: 自動ノートが英語で保存され `data` を持つ、日本語の summary で警告が付き、英語なら付かない。

## 106-2: 訳文のキャッシュと訳すワーカー

ファイル: 新規 `src/translation_store.h` / `.cpp`、`CMakeLists.txt`、`src/main.cpp`（起動・停止）、`src/ipc_server.cpp`、`src/mcp_server.cpp`、`src/cli.cpp`、`src/dummy_llm.cpp`（テスト用の返事）、新規 `tests/translation_smoke.cpp`。

- `TranslationStore`（自分の mutex だけを持つ）:
  - `Lookup(text, lang) -> optional<string>`: キャッシュを引く。英語や空文字、訳さない言語なら原文を返す。
  - `Request(texts, lang)`: キャッシュにないものだけを待ち行列に入れる。キャッシュにあるもの、待ち行列にあるもの、訳している最中のもの、失敗して待っているもの（下）は入れない。何度呼ばれても、同じ原文・同じ言語で LLM を呼ぶのは 1 回だけ。
  - 変更の通知: 訳ができたら、ダッシュボードと Web UI が差し替えられるよう、変更の番号（`translationRevision`）を上げる。`taskqueue_changes` と同じ形で取れるようにする。
  - 保存: `translations/<lang>.json` に書く（書き込みは間引く。終わるときに必ず書く）。
- 訳すワーカー: 待ち行列から最大 50 件・8,000 文字ずつ取り、`translate-llm` のプロセスを起動する。プロンプトには「入力の JSON 配列を <言語名> に訳し、同じ長さ・同じ順の JSON 配列だけを返す。id、パス、コマンド、`${...}`、コードの書式（バッククォート）、数字はそのまま」を入れる。返事の配列の長さが違う、JSON でない、のときはその回を捨てて記録し、同じ文を 3 回失敗したら 1 時間は頼まない。
- 失敗した文は「失敗して待っている」として覚え（キャッシュと同じファイルに保存し、再起動しても残す）、1 時間は `Request` されても頼まない。3 回失敗したら、原文が変わるか `translate_clear` されるまで頼まない。
- 設定: 上の「仮の決定」の `translate_mode` / `translate_engine` / `translate_model`。設定が変わったら待ち行列を捨てる。キャッシュの訳は捨てない。
- IPC / MCP / CLI: `translate_get {texts, lang}`（訳と、まだのものの一覧を返し、まだのものは頼む）、`translate_status`（件数、待ち、失敗、エンジン）、`translate_clear [--lang]`。CLI は `hancho-cli translate get|status|clear`。
- テスト: dummy LLM で、頼む → 訳が入る → 引ける、同じ原文を何度頼んでも LLM の呼び出しは 1 回（訳している最中に頼み直しても 1 回）、再起動後に同じ原文を頼んでも呼ばない、設定を変えても既存の訳で呼ばない、失敗した文は 1 時間頼まない、原文が変わると引けない、返事の配列の長さが違うと捨てる、`off` では頼まない、再起動してもキャッシュが残る、上限で古いものから捨てる。

## 106-3: ダッシュボードで訳を出す

ファイル: `src/gui_dashboard.cpp`、`src/task_lineage_view.h`、`src/bt_debug_view.cpp`、テスト（表示の文字列を組み立てる関数の単体テスト）。

- 「対象の項目」を描くところで、文字列を直接出さず、1 つの関数 `DisplayText(text, field)` を通す。表示言語が英語なら原文。そうでなければ `TranslationStore::Lookup` を引き、なければ原文を出して `Request` する。
- 一覧を作るときに、見えている行の分をまとめて `Request` する（1 行ずつ頼まない）。カードの本文とトリアージの詳細は、開いたときだけ頼む。
- `translationRevision` が上がったら、見えている一覧と詳細ペインを描き直す（選択とスクロールを保つ）。
- 訳を出している項目は、ツールチップに原文を出す。詳細ペインに「原文を表示 / 訳を表示」の切り替えを置く（`Tr(L"原文を表示", L"Show original", L"Ver original")`）。
- 描くたびに `TranslationStore` を引かない。ダッシュボードの中に (原文, 言語) → 訳 の表を持ち、`translationRevision` が上がったときだけ引き直す。`Request` も、その表にない原文だけを、一覧を作り直したときに 1 回送る。
- 表示言語を切り替えたら、見えている行のうち、その言語の訳がまだないものだけを頼む（ja → en → ja と切り替えても、ja の訳はキャッシュから出る）。
- 検索（102-x の `query`）は原文と、キャッシュにある訳文の両方に当てる。
- テスト: 英語の UI では訳を引かない、キャッシュがあれば訳、なければ原文と依頼、ツールチップに原文、同じ一覧を 100 回描き直しても依頼は 1 回、言語を往復しても訳し直さない。
