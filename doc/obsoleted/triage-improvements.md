# トリアージが「読める」ようになりました

失敗したジョブのカードを開いたとき、最初に目に入るのが `failure class: timeout` と、延々と続くタスクファイルのパスだったら——原因を調べる前に、ちょっと疲れてしまいます。

Hancho のトリアージは、そこを変えました。最初に読むのは、**LLM が書いた「何をしようとしていて、何が起きたか」の要約**です。原因やログの詳細は、そのあとに続きます。

## これまでのトリアージ

トリアージカードは、失敗したジョブやプロセスを 1 枚のカードにして、原因・候補・推奨をまとめる仕組みです。便利な反面、情報が多く、次のような引っかかりがありました。

- 原因の前に「このジョブは何をしようとしていたのか」がない
- タスクファイルのパスが長く、内容を追うのが大変
- ダークテーマだと候補のラジオボタンの文字が黒くて読めない
- せっかくトリアージしているのに、LLM の助けが見えない

この 4 つをまとめて直しました。

## 改善 1: 先頭に「要約」

情報ペインの先頭に、**LLM による自己完結の要約**が入りました。

要約には、次のような内容が 1 つの文章としてまとまります。

- 対象は何をしようとしていたか
- 何が起きたか（失敗の内容）
- 原因の見立て
- 人が何を判断すべきか

ポイントは、**「どこかのファイルを見てください」で終わらせない**ことです。長いパスやログの場所ではなく、判断に必要な中身を要約に書きます。カードを開いて要約を読むだけで、ある程度の見当がつきます。

既定の「迷うときだけ」モードでは、LLM が設定されていれば、まだ要約のない判断待ちカードに要約が自動で付きます。同じ LLM 呼び出しで助言も返るため、要約のためだけに別の相談をもう一度押す必要はありません。

## 改善 2: 「目的」セクション

要約の次に、**目的（intent）**が入りました。

失敗したジョブでは、ジョブに取り込まれている instructions の本文を表示します。これまでは `tasks/.../build.md` のようなパスだけが手がかりで、内容を確認するにはファイルを開く必要がありました。いまはカードの中に「何を頼まれていたのか」が書かれています。

対象によって、目的の見え方は少し変わります。

- **ジョブ失敗**: instructions の本文（長い場合は先頭部分）
- **プロセス失敗**: 実行していたコマンド
- **BT エスカレーション**: ツリーの目的（設定されていれば）
- **見積もり乖離・リソース待ち**: ジョブの要約

## 情報の並びを「判断の順」に

情報ペインの並びも変わりました。

```
要約 → 目的 → 原因 → 背景 → 環境 → 条件 → 理由
```

以前は原因が先頭でした。いまは、**まず全体像をつかみ、次に何をしようとしていたかを見て、そのあとで原因の詳細を読む**順番です。

たとえば、ビルドジョブがタイムアウトしたカードなら、次のように読めます。

**Before**

```
原因
  失敗分類: timeout
  最後の出力: ... C:\...\tasks\2026\11\16\build.md ...
```

**After**

```
要約
  ビルドは配布用バイナリを作ろうとして、リンク処理の直前で
  タイムアウトしました。原因はビルド時間の見積もり不足の可能性が
  高いです。タイムアウトを延ばして再実行するか、ビルド手順を
  見直すかを判断してください。
目的
  ビルド手順: （instructions の本文）
原因
  失敗分類: timeout
  ...
```

## 読めなかった文字も直しました

ダークテーマで候補のラジオボタンの文字が黒くなっていた問題も修正しました。候補のラベルがテーマの文字色に従うので、どのテーマでも読めます。

あわせて、要約や目的のように文章が続くセクションでは、コロンで終わる見出し行（例: `手順:`）を落とさず表示するようにしました。

## LLM の役割と安全ガードはそのまま

要約が入っても、トリアージの安全性は変わりません。

LLM はカードにある候補から 1 つを選び、理由を説明するだけです。新しい処置を勝手に作ったり、実行したりはしません。自動実行のガード（候補の限定、自動再試行は 1 回まで、タイムアウト延長の上限など）も従来どおりです。

要約はあくまで「最初に読むための手助け」で、最終的な判断は人か、設定された自動処置のルールが行います。

## 使い方

いつもどおり、ダッシュボードの **🩺 トリアージ** を開くだけです。

- ダッシュボード: 情報ペインの先頭に要約、その下に目的・原因…
- CLI: `hancho-cli.exe triage show <id>`
- MCP: `triage_get`

LLM に相談したいときは、これまでどおり **🤖 LLM に相談** を押します。既定モードでは、要約がないカードには自動で相談が走ります。

## まとめ

今回のトリアージは、**「原因を読む前に、まず全体像を読む」**ように変わりました。

- 要約で、何が起きたかを一目でつかむ
- 目的で、何をしようとしていたかを知る
- 原因・背景・環境・条件・理由で、詳細を確認する
- 候補を選んで処置する

失敗したジョブを見るときの最初の数秒が、少し楽になればうれしいです。
